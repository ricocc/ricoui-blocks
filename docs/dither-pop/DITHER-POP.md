# Dither Pop · 网点波普风格

**Recommended**

**Halftone Textures · Tactile Objects · Playful Motion**

> A playful 2.5D UI illustration style combining toon shading, bold outlines, halftone dithering, vibrant colors, and tactile motion.

> 一种融合卡通渲染、粗描边、半调网点、鲜明色块与实体交互动效的 2.5D UI 插画风格。

本规范是 RicoUI Dither Pop 系列的设计与开发入口。新增组件、视觉修订和交互动效调整均先遵循本规范，再遵循对应组件的 API 和行为约定。目录说明与完整索引见 [README.md](README.md)。项目架构和分发规则以 [AGENTS.md](../../AGENTS.md)、[ARCHITECTURE.md](../ARCHITECTURE.md) 和 [REGISTRY.md](../REGISTRY.md) 为准。

## 1. 风格与分类

系列名称使用 **Dither Pop**，中文使用 **网点波普风格**，目录分类 slug 使用 `dither-pop`。Recommended 是官网推荐文案。系列分类可以包含不同功能的组件，如开关、文件展示和进度指示。

该系列具有三渲二的视觉特征。技术上更准确的描述是“具有三渲二视觉特征的 2.5D 矢量插画”。核心构成为 2.5D 实体结构、Toon Shading 明暗分面、Halftone / Dither 印刷纹理和 Pop Art 配色。三渲二中的空间、光源和材质方法可以用于 SVG/CSS 绘制，运行时是否采用真实 3D 由具体需求决定。

| 特征 | 系列要求 |
| --- | --- |
| 立体几何 | 有明确厚度、前后关系、接合面和遮挡 |
| 卡通渲染 | 大色块与少量清晰明暗分面 |
| 描边 | 深藏蓝轮廓强调形状，内外层级明确 |
| 光影 | 统一光源，简化高光、接触暗部与落地投影 |
| 纹理 | 网点密度、尺寸或覆盖率表达明暗及状态 |
| 透视 | 静置水平正面，局部结构可有可解释的投影 |
| 运动 | 有重量、支点、回弹和层级的实体反馈 |

## 3. 构图和空间

### 静置视角

- 正面中心对齐，外壳基线保持水平。物件厚度主要通过下侧和局部侧面表达。
- 参考图中的倾斜大图用于观察圆角、厚度和背面连接。最终默认视角以水平状态图为准。
- 开关按键的左右倾角由工作状态决定。外壳仍保持水平。
- 用固定画布或预留空间容纳最高展开状态、外伸徽章、提示光芒和投影。状态变化不推动周围布局。
- 左右对称的螺丝、端盖和装饰按同一坐标基准放置。先确定面板中心与可见面积，再分配部件。

### 连续实体

先画物件结构，再加材质。分清前面、顶面、侧壁、内腔、底部和可动零件。

相接面的共享边缘必须来自同一组坐标或同一个投影函数。运动时也要保持接合。File Organizer 曾因独立深度平面出现接缝分离，当前盒体相接面共享投影，只有松散文件做有界视差。Flip Switch 的面板与侧壁由同一角度驱动。

实体遮挡顺序通常为地面投影、底座与内腔、可动内容、前沿遮挡面、标识、反馈光芒。按组件结构调整顺序，并在极端状态截图检查。

## 4. 色彩

| 用途 | 默认参考 | 使用方式 |
| --- | --- | --- |
| 外轮廓、符号 | `#101342` / `#101940` | 深藏蓝，区分于纯黑 |
| 主体蓝 | `#1756FF` / `#0955FF` | 外壳、背板、加载反馈 |
| 暖橙 | `#FF782B` / `#FF8619` | 填充、按键、局部强调 |
| 明黄 | `#FFD528` / `#FFDA00` | 能量扫描、按键、完成反馈 |
| 白色面板 | `#FFFFFF` | 大面积内槽、顶面、内容纸面 |
| 浅蓝紫 | 参考 `#C6D3FF` | 倒角、内衬、少量材质分面 |

主色保持饱和，深色轮廓稳定。每个物件先确定一个主色与一至两个强调色。明暗变化优先用同色系分面，避免整面白色蒙层把饱和色洗淡。

上层面板默认纯白。需要纸张或其他材质时由具体设计明确说明，不自动替换成米黄色。预览区的浅色或深色背景属于官网环境，独立组件优先透明背景并保持自己的调色板。

允许通过 Props 自定义主色和强调色。内置反光、阴影与网点仍需与新色协调，至少检查默认蓝色及一种深色、一种暖色。

## 5. 描边与圆角

- 外轮廓为最强一级，内部结构为次一级，细节为最轻一级。避免每个色块都套同样粗的描边。
- 在宽约 500 单位的 SVG 画布中，外轮廓可从 3–4.5 单位、内部轮廓从 1.5–3 单位开始。按最终屏幕尺寸检查，而非只在放大图中判断。
- 外壳、面板、槽口采用一致的圆角家族。内侧轮廓沿外侧合理内缩，圆角同步减小。
- 连续外轮廓只绘一次。相邻色面共用的边缘避免叠描，尤其注意面板前沿和中缝。
- 高光采用有面积的倒角或弧面色片。高光内外边界从主体轮廓推导，不能在任意位置补一根白线。
- 深轮廓可以保留插画式边界。光影分面以填充面表达，避免用多条平行描线代替厚度。

## 6. Halftone / Dither 网点

纹理服从材质和光照。主体侧面、远离光源的边缘、接触暗部及落地投影适合加网点。正面文字和功能符号优先清晰。

| 参数 | 默认起点 |
| --- | --- |
| 网格周期 | 约 500 单位画布中 3–5 单位 |
| 点半径 | 约 0.5–1 单位，随明暗或进度调整 |
| 方向 | 一种固定网格或错行排列，局部可轻微旋转 |
| 强度 | 能读到网点，同时保留大色块与轮廓 |
| 裁切 | 限定在对应实体面或投影范围内 |

Halftone 可用规则圆点、错行圆点或不同点径表达层次。Dither 可用固定阈值阵列模拟覆盖率。不同实现可以共存，但一个物件内需保持相近印刷尺度。

- 使用 SVG pattern、clipPath 和必要的 mask 保持网点可复用、可缩放、边界干净。
- 同一物件不同面采用一致的纹理尺度。随面投影的网点可以被压缩，但不能像额外平铺的背景纸。
- 密度变化有来源，如更暗的右侧、更远的投影尾部或增加的真实进度。
- 可以用渐变 mask 控制局部覆盖率，最终视觉仍需读到点阵。不要用连续软阴影取代印刷明暗。
- 装饰纹理固定且可复现。随机数据使用确定性种子，避免刷新跳动、SSR 不一致与水合错误。
- 在实际展示宽度及高像素密度屏幕检查网点，避免太密造成脏灰或摩尔纹。

## 7. 光源、高光与投影

默认光源来自左上方。上表面和朝光倒角较亮，背光侧面较暗，投影偏右下。组件内的螺丝、徽章、按键、内腔遵循同一方向。

三种暗部分别处理。

| 暗部 | 形状和作用 |
| --- | --- |
| 侧壁分面 | 表达厚度，保持主色饱和，可叠局部网点 |
| 接触暗部 | 贴近槽口、按键底边或遮挡处，范围窄、位置稳定 |
| 落地投影 | 位于物件背后，轮廓对应底座，偏移有方向，加入轻量网点 |

高光沿几何曲率变化，可在转角变宽或渐隐。大面积平面保留干净色块。局部、低强度的渐变允许用于材质过渡和鼠标反光。优先使用少量明确色阶及网点，控制模糊和泛白面积。

投影需与底座接近，避免物件悬浮。默认采用清晰形状与印刷点阵。避免用一个与物件无关的大椭圆、厚重的通用 drop-shadow 或多层柔焦阴影代替空间设计。

## 8. 鼠标视差与三渲二运动

静置画面保持水平。鼠标进入后才出现小角度透视和光照变化，离开、取消指针或窗口失焦后回到静置状态。

- 默认从约 5–9° 的最大倾角开始，狭长物件限制幅度，避免一端明显缩小或变形。
- 使用未旋转的稳定容器测量指针归一化坐标。运动目标限定在范围内，避免动画边界反复触发进出。
- 外壳、面板和固定部件作为相连实体一起变换。额外视差只用于真实可动的文件、徽章或内层零件。
- 地面投影放在旋转实体外，保留地面平面，只做小幅反向偏移或尺度变化。
- 高光随指针缓慢移动，强度有限。描边和主体色块始终清楚。
- 触屏操作提供点击或拖动等明确行为，默认关闭悬停倾角。

这套空间关系比增加旋转幅度更重要。SVG、CSS perspective 和共享投影函数可组合使用。只在复杂三维遮挡或真实镜头成为核心需求时评估 WebGL / Three.js，并显式声明依赖。

## 9. 动效层级与状态

| 层级 | 默认节奏 | 约束 |
| --- | --- | --- |
| Hover / focus | 约 160–260ms，短距离 | 反馈只作用于当前目标 |
| 按下 / 切换 | 有阻尼弹簧或短缓动 | 有支点，不穿模，不夸张弹飞 |
| 组展开 | 约 300–450ms，有限错峰 | 收起反向排序，遮挡关系连续 |
| 真实进度 | 约 500–800ms ease-out | 支持中途更新，数字与填充共用进度 |
| 加载指示 | 约 1–2.5s 的轻量循环 | 与工作状态关联，完成时切换反馈 |
| 完成反馈 | 约 450–700ms 一次性强调 | 最终状态稳定且清晰 |

动效必须说明当前状态、可操作对象或能量变化。一次点击不能只有通用弹跳。视觉回弹不改变实际业务值，进度指示不伪造加载结果。

使用可中断的插值或弹簧。连续操作从当前视觉位置接续，及时清理旧动画与定时器。避免反复卸载反馈元素使动画每次重启。

### 当前四个组件的行为基准

- **File Organizer** 的 hover 只强调当前文件，点击控制组展开。展开后指针离开仍保持展开，外部点击或 Escape 关闭。前后文件有顺序和遮挡，光芒平滑跟随目标。
- **Flip Switch** 的按键围绕中轴翻转，底座不随 ON/OFF 状态摇摆。按下状态轻微压缩行程，橙色 O 侧和黄色 I 侧的面与侧壁保持连接。光芒可跟随悬停半区。
- **Dither Progress** 的网点、填充长度与百分比来自同一个显示进度。加载中右上三条蓝色光芒交错循环，闪电内黄色网点由下往上扫描。完成后显示勾选并把光芒变黄，三条光芒继续交错循环。鼠标移动带动外壳轻微透视、高光和反向投影。
- **GitHub Repo** 的指针移动带动卡片轻微倾角，悬停时徽章扫光并在 Stars 上方浮现蓝色光芒；星标按钮点击打开 GitHub 仓库。计数由调用方提供，reduced motion 停用装饰动效。

## 10. 可访问性与工程实现

- 遵循语义。开关使用 switch 与 aria-checked，进度使用 progressbar 与 0–100 范围，展开对象提供按钮与展开状态。装饰 SVG 对辅助技术隐藏。
- 键盘操作与 pointer 操作达到相同业务结果。保留 focus-visible，鼠标拖动时避免多余焦点框。
- `prefers-reduced-motion` 必须可动态响应。关闭非必要倾斜、循环扫描和弹簧，保留可理解的静态状态与业务功能。
- 调用方可关闭动画时，一并关闭装饰循环与鼠标倾角。不要只让数字瞬间更新。
- 每个 SVG 实例使用唯一 ID，pattern、mask、clipPath 与渐变引用保持实例隔离。
- 只在需要浏览器能力时使用 use client。服务端首次渲染确定，浏览器 API 在合适的生命周期执行。
- 动画帧、监听器和计时器在更新及卸载时清理。连续动画尽量交给 CSS，静止时避免空转的 JS 绘制循环。复杂渲染评估离屏和页面隐藏时暂停。
- Registry 组件仅依赖自身 React 源码及声明的 npm 依赖。配置 dock、演示数据、播放按钮、Copy Prompt 和官网主题管理放在 Preview 中。
- Props 清晰区分业务状态与视觉配置。受控值、默认值、取消事件和 disabled 等行为按具体组件文档落实。

## 11. 后续 Agent 的开发顺序

1. 阅读本规范、AGENTS.md 和最近的同系列组件文档。
2. 确认真实功能、默认水平视角、静态/悬停/按下/完成等所需状态。
3. 画无纹理的结构稿，检查轮廓、厚度、支点、对齐和所有状态的接合面。
4. 建立深藏蓝描边、主色和少量明暗分面，确定左上光源。
5. 沿实际轮廓构造高光与倒角，加入接触暗部和落地投影。
6. 对指定表面加网点，检查实际尺寸下的清晰度。
7. 添加状态动效，再添加有界指针视差和光影跟随。
8. 检查键盘、触屏、减少动态效果和多实例。
9. 完成官网 Preview、分类、源码、Registry、缩略图和具体组件文档。
10. 运行与改动匹配的检查。涉及新组件和 Registry 时遵循项目固定安装与构建验证流程。

## 12. 视觉验收

- [ ] 静置水平，参考图角度没有被误套到产品展示。
- [ ] 外壳、面板、螺丝及徽章对齐，圆角与内缩关系一致。
- [ ] 共享面在两端状态及极端指针方向无缝隙、重影和穿透。
- [ ] 主色饱和，白面纯净，深藏蓝轮廓有层级。
- [ ] 高光沿几何表面分布，前沿没有多条叠加的亮线。
- [ ] 投影接地、有方向，网点与实体材质协调。
- [ ] 网点表达明确的明暗或状态，文字与符号保持清楚。
- [ ] 动效有原因、有支点，循环只在适当工作状态发生。
- [ ] 减少动态效果后仍可辨认工作状态并完成操作。
- [ ] 正常尺寸、小屏、至少两种宿主背景与多实例均已检查。

验收截图至少包含静置、主要状态的两端、鼠标极端方向。对进度条增加 0%、中间进度和 100%。对文件组增加展开与关闭。先在组件实际展示尺寸查看，再放大检查接缝、描边和纹理。
